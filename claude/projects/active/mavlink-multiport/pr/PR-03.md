## Body (PR-03-body.md)

Replaces the monolithic `telemetry/mavlink.c` (~1.5k LOC) with focused modules under
`src/main/mavlink/` — runtime, ports, streams, routing, modes, command, guided — plus
`fc/fc_mavlink.c` for incoming-message dispatch. `telemetry/mavlink.c` stays as a thin
telemetry-API adapter.

New behavior on top of the move:
- Up to 4 concurrent MAVLink ports (`MAX_MAVLINK_PORTS`), per-port runtime state, per-port
  `mavlink_port{1-4}_*` settings (stream rates, `min_txbuffer`, `radio_type`,
  `high_latency`). Port 1 streams fully by default; ports 2–4 start heartbeat-only.
- ArduPilot-style routing: routes learned as `(sysid, compid) → ingress port`, targeted
  traffic forwarded only on known routes, broadcasts fanned out, no repack. Fixed local
  identity `(mavlink_sysid, MAV_COMP_ID_AUTOPILOT1)`.
- Half-duplex TX backoff keyed to real per-port RX activity on shared
  `serialrx_halfduplex` MAVLink RX ports.
- mLRS radio link stats/information/flow-control handling per port.
- HIGH_LATENCY2 service (per-port setting + `MAV_CMD_CONTROL_HIGH_LATENCY`).
- RX parsing bounded per scheduler invocation; MAVLink moved behind the
  `MCU_FLASH_SIZE > 512` gate.

The incoming message/command surface otherwise matches upstream (DO_REPOSITION,
DO_CHANGE_ALTITUDE, RC override, RADIO_STATUS, ADSB, param stub), now also accepted via
COMMAND_LONG (upstream had that dispatch commented out).

**⚠ Mission protocol is intentionally absent at this stack point.** The old ad-hoc
mission code is not carried over; a rewritten transfer state machine lands two PRs later.
Merge only as part of the stack.

19-test unit slice included (`mavlink_unittest`, 19/19). Verified: full SITL build,
warnings-as-errors, clean.

Third PR of the mavlink_multiport2 stack.
